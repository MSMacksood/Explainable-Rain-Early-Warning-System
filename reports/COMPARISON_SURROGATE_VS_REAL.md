# Surrogate vs Real Dataset — Rerun Comparison

**Real data:** fresh Kaggle download, `data/raw/SriLanka_Weather_Dataset.csv`, 23.8 MB.
The earlier 15 MB file was the offline surrogate generated by `scripts/make_demo_data.py`;
the size difference is expected (real file: 147,480 rows × 24 columns incl. `rain_sum`,
`snowfall_sum`, sunrise/sunset strings; surrogate: 142,440 × 20).
Surrogate-run artifacts are archived in `reports/surrogate_run/` and `reports/partial/`;
real-run fold records are in `reports/partial_real/`.

## Code changes required by the real data (all committed)

1. Schema normalization: `weathercode` → `weather_code`; tolerate `rain_sum`/`snowfall_sum`.
2. Zero-variance column filtering (drops `snowfall_sum`, constant 0 in Sri Lanka).
3. Phase-0 "realistic challenges" check reformulated (minority share < 0.45 OR heavy-rain share < 0.15) — the old dry-share heuristic wrongly failed on a 65.7%-rainy country.
4. Benchmark CatBoost now uses eval-set early stopping (same protocol as the Optuna objective).
5. API schema gained `apparent_temperature_max/min` (they survive correlation filtering on real data, unlike the surrogate where `heat_index_f` survived instead — the filter is data-driven).

On real data the weakest cell is the **dry zone under the Maha (NE) monsoon** — the paddy
heartland and the very season/region of Ditwah's US$814M agricultural damage — not the hill
country as the surrogate suggested. The thesis equity audit (Ch. 6) has been rewritten
accordingly; the reversal itself is now cited as evidence that fairness conclusions must be
re-derived from real data.

## Top SHAP drivers

Surrogate: monsoon_phase, month_cos, precipitation_sum, precipitation_hours.
Real: **precipitation_hours, precip_to_et, precipitation_sum, monsoon_phase, precip_lag2, climate_zone** — persistence/moisture state first, then season, then geography.
